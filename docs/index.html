Local platform engineering demo

Run NullClaw-like agents as managed runtimes.

Aquarium wraps an imported NullClaw runtime with an operator console, Infisical-backed secrets, LiteLLM budgets, per-runtime keys, diagnostics, and a local SSO perimeter.

GitHub repository MIT license Architecture notes
Architecture

A control plane around the runtime, not a fork of it.

Aquarium treats upstream NullClaw as imported runtime source. The platform work lives at the boundary: lifecycle, secrets, model access, limits, diagnostics, and operator workflows.

Operator UIDjango + Unfold surfaces for agents, runtimes, secrets, diagnostics, and chat.
OrchestratorPython 3.12 service layer and CLI for runtime lifecycle and key provisioning.
InfisicalSecret source of truth with runtime-scoped projects and secret references.
NullClawHosted agent runtime launched with generated config and isolated state.
LiteLLMMandatory model gateway for per-runtime keys, budgets, RPM/TPM, and spend tracking.
Provider master keys stay in the LiteLLM core scope. NullClaw runtimes receive only a per-runtime LiteLLM key, the LiteLLM base URL, and non-LLM secrets such as Telegram credentials.
Setup

Bootstrap the real local stack.

The project is intentionally real-only. A complete run requires real provider credentials and, if Telegram is enabled, a real bot token.

RuntimeHomebrew Python 3.12 and a repo-local `.venv`.
ContainersDocker Compose projects named with the `aquarium-` prefix.
SecretsInfisical CLI login plus real OpenRouter and optional Telegram credentials.

Secrets

Secrets are centralized, scoped, and injected.

Infisical is the source of truth. Aquarium creates or uses one secret scope per runtime and keeps provider master credentials out of runtime scopes.

LiteLLM core projectStores `LITELLM_MASTER_KEY`, `OPENROUTER_API_KEY`, and future provider master keys. Runtime containers do not receive these secrets.
Runtime projectStores `LITELLM_API_KEY`, `TELEGRAM_BOT_TOKEN` when enabled, allow-list values, and runtime-specific integration secrets.
Secret contract example
runtime_project:
  env: prod
  path: /runtime
  secrets:
    - LITELLM_API_KEY
    - TELEGRAM_BOT_TOKEN
    - TELEGRAM_ALLOW_FROM
LiteLLM

Model access goes through runtime keys.

LiteLLM is the mandatory gateway between hosted runtimes and providers. The orchestrator provisions per-runtime keys and stores them back in Infisical.

BudgetsEach runtime key can carry a spend budget.
Rate limitsRPM and TPM limits are enforced before traffic reaches the provider.
RevocationOperator actions can rotate or revoke a runtime key without exposing provider credentials.

LiteLLM UI is internal-only on loopback. The fallback login uses username `admin` and the current LiteLLM master key.

Infisical

The secret store is independent of the runtime.

Infisical keeps its own app-level authentication. The perimeter can gate access to the UI, but Infisical remains the authority for projects, environments, service tokens, and secret values.

Useful endpoints

Perimeter auth

Use the HTTPS perimeter for browser work.

The supported browser path is Caddy + Authelia over local trusted TLS. The `lvh.me` aliases resolve to localhost without editing `/etc/hosts`.

Control planehttps://app.lvh.me/admin/
Auth portalhttps://auth.lvh.me/
Secrets UIhttps://secrets.lvh.me/
Trusted local TLS
make perimeter-tls
make perimeter-bootstrap
make perimeter-up
make perimeter-health
Authelia login for the local demo is `admin` / `admin`. If Django asks for its own bootstrap login, use `admin` / `admin` as well.
Create a bot

Draft first, launch explicitly.

The Agent Builder creates a draft agent. Launch is a separate action from Agent Studio, which makes the runtime boundary visible and keeps secret validation explicit.

SlugThe permanent technical name used in URLs, runtime ids, Docker services, Infisical projects, and local folders.
PersonalityChoose a preset card or open Custom Prompt for a hand-written system prompt.
TelegramIf enabled, bind a Telegram Bot Secret. The UI stores a secret reference, not the token value.
Launch and test

Runtime launch creates config, keys, and state.

At launch time Aquarium compiles the prompt and selected skills, creates or updates the runtime, provisions a LiteLLM key, writes per-runtime config, and starts the gateway.

Runtime health

Diagnostics

The operator UI shows cached state first.

Normal page loads are read-only. Live probes, secret checks, smoke tests, and diagnostics refreshes are explicit operator actions, so ordinary GET requests do not put write pressure on SQLite.

Cached summariesFast pages for health, lifecycle, diagnostics, and recent action status.
Explicit refreshOperator actions perform live runtime checks and persist the new snapshot.
Troubleshooting

Separate service health from browser auth.

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
Control plane maintenance
make controlplane-migrate
make controlplane-bootstrap-operator
make controlplane-check
Do not commit `.env`, generated runtime config, service-token env files, or `perimeter-stack/certs/`. Secrets belong in Infisical, not in the repository.
